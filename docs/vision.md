# Vision — the longer horizon

This document is deliberately separate from the v0 build. It exists so the bigger picture is recorded without contaminating the discipline of building one concrete thing first.

## The v0
One local, private desktop app that delivers personalized future-self visualization sessions as audio. Build it, use it, judge it.

## The next steps after v0
Once the future-self template works end to end and the founder is satisfied with its quality:

1. **Build a second protocol** — concretely, the same way. A strong candidate is performance / event rehearsal: also non-clinical, broadly wanted, easy to feel whether it worked.
2. **With two real templates side by side, extract the shared engine.** What do future-self and rehearsal genuinely have in common — intake, generation, voice, memory, the return structure? That common structure, *discovered* from real code rather than guessed at, becomes the engine. This is the right way a platform is born: as the residue of concrete products, not as an up-front abstraction.
3. **Then, and only then, the flexible-engine vision becomes a real possibility:** a product where the user describes what they want to work on and the engine assembles a personalized, local, private session protocol for them — many protocols, one private local engine.

## The harder problems waiting at the platform stage
These are real and should be met concretely when the project reaches them — not pre-solved now:
- Running reliably on machines that aren't the founder's (varied chips, OS versions, memory).
- Packaging multi-gigabyte models so non-technical users can install without a terminal.
- The long tail of edge cases once strangers depend on the product.
- The ongoing human ownership of a live product — updates, support, failures.
- Protocols that are clinical or trauma-adjacent — which need de-escalation machinery and clinician input designed in.

When the project reaches that stage, the founder will have built enough concretely to assess honestly — from her own hands — what the platform genuinely requires, including whether the team needs to grow.

## The principle that holds all of this together
Concrete first. Abstraction extracted, never poured in advance. One template, then two, then the engine. The platform is the destination, not the starting point — and the way to reach it is to build the next single concrete thing, every time.
